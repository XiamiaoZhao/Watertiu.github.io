行！整！——专属旅行网页生成器

依据：本旅行网页聊天、独立拙政园与五处历史语音导览聊天，以及保存的欧洲旅行口袋站页面。整理日期：2026-10-26。

产品目标与发布方式

填写人数、目的地、旅行日期，补充自愿提供的偏好和已购订单，得到可在手机使用的专属旅行口袋站。游客免登录生成、编辑、预览、导出和分享；管理员选择行程发布为 XiamiaoZhao/Watertiu.github.io 中的独立网页。原有旅行网站与仓库首页保留。

之前已经明确的全部要求

| 模块 | 要求 |

| --- | --- |

| 品牌 | 行！整！，含义是立即出发；左上角使用已确认的黑色毛笔方形 logo，有笔锋、简洁山川缺口。 |

| 视觉 | 高级、古风、水墨或精致手绘；当地古建筑与文化特征；每天不同绘画；插画只作装饰，不伪装成真实照片。 |

| 手机 | 手机优先，文字不溢出，点击区域够大；首页紧凑；内容分成独立页面，右上角目录；减少解释性长文。 |

| 每日行程 | 到达、入住、游览、用餐、休息、离开完整串联；有必去与可替换项、预约时段、步行量与交通缓冲；点击直达当天 City Walk。 |

| 日历 | 周一开始、每行七天；跨月连续显示；当天以前的旅行日期画两组足迹；按行程时区计算，不提前标记当天。 |

| 行程调整 | 增删城市、压缩停留天数、整体提前或延后、延长至返家；修改酒店只重算受影响日期的路线端点；已购票与明确预约不可悄悄移走。冲突必须列出。 |

| City Walk | 按大致真实地理位置画点位、主要街道、河流、桥、建筑；精致纸本地图；标推荐顺序、相邻点交通方式和约时；不要捏造精准距离。可缩放、点击景点。 |

| 沿途小吃 | 与正餐分开；地图标出顺路、值得尝的小吃，大致位置、推荐品种、绕行程度；不把远店伪装成顺路。 |

| 景点详情 | 侧栏或手机底部抽屉；真实场景照片与来源、简介、预计停留、预约、票价、购买渠道、语音导览入口。 |

| 照片 | 优先真实、对应景点或藏品的照片；有作者、来源、授权字段；缺图不用不相关照片或生成图冒充。可由管理员补充有使用权的素材。 |

| 饮食 | 餐馆与小吃分区；具体分店、地址、特色菜、人均预算、顺路时段；小红书、鸭觅、当地公开资料可作体验线索，不能声称读过未访问的评价。 |

| 外部 App | 高德导航、美团店名预填搜索、小红书对应搜索/笔记；手机优先尝试唤起 App，失败提供带关键词的网页备用；微信等内置浏览器可能阻止跳转。 |

| 票务 | “资料”改成实际购票或预约渠道；官方、微信、美团等；70 周岁以上免票需有证据，注明预约是否另需办理、凭证与适用项目。门票、游船、特展不混为一谈。 |

| 酒店 | 名称、地址、入住和退房日期、房型、人数、费用、已订/待订；同店连续住宿合并；未订提供区域建议；变更住宿联动行程。 |

| 城际交通 | 火车或飞机等可选，时间优先或费用优先；明确出发/到达车站或机场、发到时间；已购车次保留；离开车站也有高德导航；无实时票务数据不编班次和余票。 |

| 天气 | 每日最高/最低温、天气、更新时刻；超出预报期明确“暂无预报”，历史气候与实时预报分开；不复制旧日期温度到新行程。 |

| 语音导览入口 | 独立子目录，可按景点选择；复用拙政园地图式体验；漂亮地图中点景点开始对应讲解。 |

| 语音播放器 | 自然中文人声，前后 15 秒、上一/下一点、倍速、字幕、全文、进度、已听记录；播放需要用户操作；不可用只有展室概述来代替藏品讲解。 |

| 讲解质量 | 开篇历史与美学，具体人物、时代、工艺、建筑、文物价值与地位；拒绝空洞抒情；重要事实有来源；小红书体验不能充当唯一史实依据。 |

| 博物馆 | F1/F2/F3 总图定位展室；展室内小地图；每室 5–8 件重要藏品、独立讲解、真实照片，另有展室总览；无法确认柜位时使用照片索引，不画假柜位。 |

| 旅行助手 | 待确认清单、预约提醒、拍照点、交通购票提示；打印/离线查看与备份导入导出。 |

| 国内使用 | 不依赖 Google、境外字体/CDN；资源尽量同源；地图改高德。GitHub Pages 的国内可达性不能保证，架构允许将同一静态包镜像到国内服务。 |

| 公开范围 | 当前个人旅行曾授权公开酒店地址、日期、车次；该授权不扩展到新用户。新行程默认分享隐藏酒店详情和具体交通订单，不收身份证号、支付信息、订单号与乘客姓名。 |

输入设计

**必填**：出发日期、结束日期、出行人数（至少一位成人）、目的地及顺序。每城停留天数可自动平均分配，也可自行修改，总数须与总天数一致。

**选填**：行程名称、出发城市、同行老人与儿童人数、节奏、日步行上限、兴趣、饮食要求、每晚住宿预算、交通优先项、喜欢的交通方式、旅行时区；必去/不去的景点及指定日期时段；已订酒店；已购火车/机票、出发到达站与日期时间；需要讲解的景点；手动补充地点坐标；分享范围。

预订截图是辅助输入，不直接公开。可由配置后的多模态接口或本地文字识别提取字段，必须让用户校对；未接识别时明确提供结构化手工输入。识别后的乘客姓名、身份证、订单号应丢弃。

程序与 AI 的职责

| 交给程序（无需语言模型） | 可选 AI（仅按需） |

| --- | --- |

| 日期校验、七列日历、足迹、页面排版、目录、主题、导航链接、表格、导出、压缩分享、GitHub 发布 | 把零散文字整理成结构化偏好；复杂需求理解 |

| 固定票与酒店锁定、预约冲突、闭馆提示、缓冲、景点去重、区域聚类、路线排序、受影响日期增量更新 | 对资料库未覆盖的城市提出景点候选和主题；只输出数据，不写整页 HTML |

| 复用城市资料包、真实坐标投影、街河地图、照片索引、购票入口、餐馆分类 | 对有来源的材料写历史、工艺与艺术讲解；生成后审核并缓存 |

| 天气 API、POI/路线 API、票务查询链接、素材缓存、语音播放器 | 订单图识别（可用专门 OCR 替代）、一次性新增城市插画 |

| 已有语音和素材按内容版本复用、字幕同步、播放进度 | 新讲稿的语音合成走专门 TTS 接口，按文字缓存，不能每次生成行程都重新朗读合成 |

降低 token 的具体方式

1. 城市资料与模板分离。一个城市包供所有用户复用；生成网页本身无需模型。

2. 发送精简字段与景点 ID，不发送整段聊天、HTML、照片二进制或已有长讲稿。

3. 日期、酒店、人数和交通变化交给约束引擎；只有用户明确请求补充新内容才调用 AI。

4. AI 每次输出有长度限制的 JSON；对结构、名单、URL、字数进行校验；价格、开放和柜位不接收无依据推断。

5. 请求规范化后计算摘要，相同模型/提示词版本/资料版本复用结果；界面展示实际接口 usage，未调用显示 0。

6. 图片、自然语音与深度讲解按城市/景点制作一次，供多个行程使用；无需逐用户重复生成。

7. 游客不承担自动后台调用；明确点“AI 补充”才调用。公共服务必须配置鉴权、限流与额度，不将接口密钥放进网页或仓库。

架构与真实边界

- 静态应用：表单、规划引擎、地图、内容库、专属查看器均能在 GitHub Pages 运行。分享 URL 携带经过隐私筛选的压缩行程；它是可转发的公开链接，不是加密保险箱。

- 独立网页：管理员在专用发布页选择行程，预览公开字段后保存到固定 `xingzheng/trips/<随机标识>/index.html`。GitHub 令牌仅存在当前页面内存，不能进 localStorage、分享链接、导出和日志。

- 扩展服务：本地 Node 服务提供可选 AI 和天气代理；接口密钥只读取服务器环境变量。GitHub Pages 不运行服务器代码；要向公众提供 AI 需另部署该服务并设置可信域、访问码/身份体系、限流。

- 现成资料覆盖徐州、苏州、上海、福州、泉州和原有 8 处导览。其他城市可以输入自选景点生成结构化口袋站；未获得可信坐标、照片和讲解时显示待补充，不宣称同样的内容深度。

- 此版本不是自动抓取小红书/美团/鸭觅登录内容的爬虫，也没有实时余票数据。已有城市资料的核查日期保留；出发前需要更新营业、票价和预约。

验收

1. 空白用户完成必填项后能生成，且不用登录和 AI。

2. 七天一行、跨月与时区足迹正确；手机宽度 360px 起不横向溢出。

3. 已购交通时间与预约不被覆盖；时间不够时给冲突，不强行塞入。

4. 换某一晚酒店只更新受影响日；原有景点计划保留，并说明影响。

5. 生成与分享不带 token、原始截图、姓名、订单号；默认隐藏具体酒店和车次。

6. 详情照片与景点一致；新地点无坐标时不虚构地理地图。

7. 自定义文字无法注入脚本；导入与分享有体积限制；GitHub 发布路径不可逃逸目标目录。

8. 导出网页可离线打开已保存的行程文字与地图；外部照片、音频、导航仍需网络，界面明确区分。

9. 分享给另一台设备能还原行程；管理员发布后有可访问的专属网址。

10. AI 未配置时不显示生成成功；接入后记录实际调用量、命中缓存不再发请求。
